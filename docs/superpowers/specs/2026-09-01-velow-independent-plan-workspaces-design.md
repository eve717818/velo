# Velow Notebook 四级独立计划工作台设计规格

- 日期：2026-09-01
- 状态：已确认，待实施
- 产品：Velow Notebook
- 范围：日计划、周计划、月计划、学期计划的数据归属、页面结构、任务交互与旧数据迁移
- 取代规则：本规格取代此前“日任务自动汇总到周/月/学期”和“跨日任务色带”的展示与数据规则；此前响应式、右滑完成、学期/假期管理和离线能力中不冲突的部分继续有效

## 1. 背景与目标

现有计划工作台以具体日期任务为唯一来源，周、月和学期视图通过日期范围自动汇总同一批任务。该结构造成三类问题：四个视图内容重复、周历/月历占用大量空间、跨日任务与范围总体计划增加理解和维护成本。

本次改版把计划工作台收敛为四个彼此独立的任务清单：

1. 日任务只出现在某一天的日计划。
2. 周任务只出现在某一自然周的周计划。
3. 月任务只出现在某一自然月的月计划。
4. 学期任务只出现在某个学期或假期的长期计划。
5. 四个页面共享当前日计划的长条任务卡、右滑完成、撤销和简洁进度表达。
6. 周历、月历、跨日任务色带和周/月总体计划抽屉退出产品界面。

目标是让用户先选择计划层级，再直接创建和完成该层级的任务，不需要理解日期汇总、任务复制或跨日关系。

## 2. 核心产品规则

### 2.1 单一归属

每条任务必须且只能属于一个计划层级。任务保存后不会自动显示在其他层级，也不会参与其他层级的任务数量或完成进度。

### 2.2 同层级移动

任务可以移动到同一层级的另一个周期，例如本周移到下周、九月移到十月。任务不能通过普通编辑直接改变层级。需要跨层级安排时，用户在目标层级新建任务，避免隐式复制或数据联动。

### 2.3 当前周期

- 日计划当前周期为一个自然日。
- 周计划当前周期为周一至周日的自然周。
- 月计划当前周期为自然月。
- 学期计划当前周期为用户选择的学期、寒假、暑假或自定义假期。

### 2.4 完成方式

四个层级统一使用右滑完成。任务卡常驻方向箭头，滑动进度驱动卡片填充；达到阈值后显示“已完成”，并提供撤销。任务菜单和键盘操作继续提供等价完成方式。

## 3. 方案决策

采用统一 `PlanTask` 表增加 `scope` 与 `periodKey`，而不是建立四张任务表或维护日期任务与高层计划任务两套模型。

原因：

- 右滑、编辑、删除、离线持久化和排序逻辑只需维护一次。
- `scope + periodKey` 能在数据库层清晰表达隔离边界。
- 迁移可以原地保留现有任务 ID、完成状态和时间戳。
- 后续增加搜索或统计时仍可查询统一任务表，但产品页面不会自动跨层级汇总。

未采用的方案：

- 四张任务表：隔离直观，但会复制服务、索引、测试和迁移逻辑。
- 保留日期任务并新增高层任务表：会产生两套任务身份和完成状态，容易形成重复数据。

## 4. 数据模型

新增类型：

```ts
export type PlanTaskScope = "day" | "week" | "month" | "semester"

export interface PlanTask {
  id: string
  scope: PlanTaskScope
  periodKey: string
  title: string
  subject?: string
  estimatedMinutes?: number
  notes?: string
  startMinutes?: number
  isCompleted: 0 | 1
  completedAt?: number
  order: number
  createdAt: number
  updatedAt: number
}
```

字段约束：

- `day.periodKey`：`YYYY-MM-DD`。
- `week.periodKey`：该自然周周一的 `YYYY-MM-DD`。
- `month.periodKey`：`YYYY-MM`。
- `semester.periodKey`：`LearningPeriod.id`。
- `startMinutes` 只允许日任务使用；其他层级保存时必须忽略或清空。
- 每个任务必须通过领域函数校验 `scope` 与 `periodKey` 的组合。

IndexedDB 新索引：

```text
id, [scope+periodKey], scope, periodKey, [scope+periodKey+isCompleted], isCompleted, updatedAt
```

`LearningPeriod` 继续保存学期、寒假、暑假和自定义假期。学期计划的用户可见名称保持“学期计划”，其周期选择器可包含上述四种长期周期。

## 5. 数据迁移

数据库升级到下一版本时执行一次事务迁移：

1. 每条现有 `PlanTask` 写入 `scope: "day"`。
2. `periodKey` 使用原 `scheduledDate`。
3. 保留任务 ID、标题、科目、时长、备注、完成状态、完成时间、排序和创建/更新时间。
4. 原跨日任务的每个步骤成为独立日任务；清除 `groupId`、`stepIndex` 和 `stepTitleMode`，不再产生跨日联动。
5. `planTaskGroups` 和 `rangePlans` 旧表暂时保留但停止读取和写入，避免不可逆删除；后续数据清理需单独规格。
6. 任意一条任务校验失败时回滚整个升级事务，不能产生部分迁移。

迁移后，现有任务只出现在对应日期的日计划。周、月和学期计划初始为空，由用户分别创建。

## 6. 信息架构

顶部保留四个视图切换：`日 / 周 / 月 / 学期`。内部路由值可继续使用 `period` 表示学期视图，避免无意义的路由兼容性变更。

### 6.1 统一页面骨架

四个视图共享以下结构：

1. 当前层级名称和当前周期。
2. 上一周期、下一周期与周期选择入口。
3. 当前周期任务数量和完成进度。
4. 长条任务清单。
5. 明确的“新建任务”按钮。
6. 任务为空时的简短说明与创建入口。

页面不再显示周历、月历、跨日色带、选中日期侧栏、周/月总体计划摘要或额外抽屉。

### 6.2 日计划

- 保留当前日计划的日期选择方式。
- 保留“定时安排”和“待安排”两个区域。
- 只有日任务可以设置具体时间。

### 6.3 周计划

- 标题显示周一至周日，例如“8月31日—9月6日”。
- 使用上一周、下一周按钮和日期选择器定位自然周。
- 页面只显示该周创建的周任务，不显示任何日任务。
- 单一“本周任务”列表，不再拆成七天。

### 6.4 月计划

- 标题显示月份，例如“2026年9月”。
- 使用上一月、下一月按钮和月份选择器。
- 页面只显示该月创建的月任务，不显示日任务或周任务。
- 单一“本月任务”列表，不显示月历。

### 6.5 学期计划

- 顶部使用紧凑的学期/假期选择器。
- 支持新建、编辑和删除学期、寒假、暑假及自定义假期。
- 页面只显示绑定到当前长期周期的学期任务，不按任务日期查询。
- 未创建长期周期时显示“创建学期或假期”的空状态。

## 7. 任务卡与交互

### 7.1 内容层级

任务卡使用当前日计划的横向长条结构：

- 标题为第一视觉层级。
- 科目与预计时长使用次级文字。
- 备注不在列表完整展开，只在编辑或详情中展示。
- 页面已经表达计划层级，因此任务卡不重复显示“日/周/月/学期”标签。
- 长标题单行省略；200% 文本放大时任务卡允许增高并保持控件不重叠。

### 7.2 右滑完成

- 未完成任务左侧常驻低对比度流动箭头。
- 手指右滑时填充和位移跟随进度。
- 达到既有阈值后提交完成状态，显示“已完成”并切换为低饱和紫灰毛玻璃表面。
- 未达到阈值时回弹。
- 完成成功后提供 5 秒撤销；失败时恢复原状态并提供重试。
- 竖向滚动不得触发完成；减少动态效果时直接切换状态但保留文字反馈。

### 7.3 编辑与移动

- 点击任务卡打开任务操作。
- 编辑表单锁定当前 `scope`，允许修改当前层级的 `periodKey`。
- 日任务可以修改日期和时间。
- 周、月和学期任务分别使用周、月和学期选择控件。
- 删除与恢复继续使用现有确认、错误和焦点恢复规则。

## 8. 新建任务表单

通用字段：

- 任务标题：必填。
- 科目：可选。
- 预计时长：可选正整数。
- 备注：可选。

层级字段：

- 日计划：日期与可选时间。
- 周计划：所属周，默认当前周。
- 月计划：所属月，默认当前月。
- 学期计划：所属学期或假期，默认当前选择。

创建入口从当前页面携带 `scope` 和 `periodKey`，表单不提供跨层级切换。原“单日任务 / 跨日任务”模式切换移除。

## 9. 领域与组件边界

建议新增或重构：

- `plan-period-keys.ts`：生成和校验日、周、月、学期 `periodKey`。
- `PlanTaskListView`：周、月、学期共用的任务清单与空状态。
- `PlanPeriodNavigator`：按层级显示周期标题、上一期、下一期和选择控件。
- `TaskEditorDialog`：接收锁定的 `scope` 与 `periodKey`，渲染对应周期控件。
- `usePlanWorkspace`：改为按 `[scope+periodKey]` 查询，进度仅基于当前查询结果。
- `PlansPage`：只编排视图、周期导航、进度和统一任务操作。

保留：

- `TaskBar` 的右滑、撤销、键盘和视觉反馈。
- `LearningPeriodDialog` 与长期周期管理能力。
- IndexedDB、本地优先、PWA 离线和错误恢复机制。

退出主流程：

- `WeekPlanView` 七日网格。
- `MonthPlanView` 月历与选中日期面板。
- `TaskGroupBand`、跨日任务创建与任务组编辑入口。
- `RangePlanSummary`、`RangePlanDrawer` 和周/月总体计划读写。

旧组件和旧表的物理删除不与本次功能改版捆绑；确认没有兼容或回滚需求后再单独清理。

## 10. 数据流

```text
视图 + 当前周期
      ↓
生成 scope + periodKey
      ↓
IndexedDB 组合索引查询
      ↓
当前层级任务列表与独立进度
```

```text
当前页面点击新建
      ↓
表单锁定 scope，默认当前 periodKey
      ↓
校验层级与周期键
      ↓
事务保存 → live query 刷新当前列表
```

```text
右滑达到阈值
      ↓
更新当前任务完成状态
      ↓
仅刷新所属层级与周期 → 提供撤销
```

## 11. 错误处理与可访问性

- 非法或缺失 `periodKey` 阻止保存，并在周期控件旁显示错误。
- 学期任务引用不存在的长期周期时不静默迁移；显示可恢复错误并引导重新选择。
- 保存失败保留全部输入和当前页面位置。
- 所有周期导航与创建按钮触控区域不少于 44×44 CSS px。
- 右滑必须有任务菜单和键盘等价操作，状态不只依赖颜色。
- 对话框保持焦点进入、焦点返回、Esc 关闭和背景不可操作。
- 所有非必要动效尊重 `prefers-reduced-motion`。

## 12. 响应式规则

- 手机、平板竖屏、平板横屏和桌面均使用单列任务清单作为主内容。
- 手机周期导航允许标题与按钮换行，但任务卡始终占满内容宽度。
- 平板与桌面可将紧凑进度卡放在任务列表旁或上方，但不得压缩任务卡到难以阅读。
- 任务列表设置合理最大宽度并在大屏居中；不把任务拉伸成难以扫读的超长文本行。
- 页面不得产生横向滚动；任务标题、元信息和完成状态必须在 200% 文本放大时保持可读。
- 不使用固定高度容纳任务列表；长列表采用页面自然滚动。

## 13. 测试与验收

### 13.1 数据与迁移

- v4 数据升级后所有现有任务成为日任务，字段和完成状态不丢失。
- 跨日步骤独立化后不再保留任务组关联。
- 日、周、月、学期 `periodKey` 的生成和校验覆盖跨月、跨年、闰年和不存在学期。
- `[scope+periodKey]` 查询只返回当前层级和当前周期任务。
- 同层级移动成功，跨层级编辑被拒绝。
- 升级事务失败时不产生半迁移数据。

### 13.2 组件

- 四个视图都渲染统一任务卡、独立进度和空状态。
- 日计划保留定时与待安排；周、月、学期为单一任务列表。
- 周/月页面不存在日历、日期单元格、跨日色带和总体计划抽屉。
- 学期未创建、已选择、切换、编辑和删除状态完整。
- 新建与编辑表单锁定层级并显示正确周期控件。
- 原跨日模式入口不可见。

### 13.3 交互与浏览器

- 四个层级均可新建、编辑、删除、右滑完成、恢复和撤销。
- 右滑与竖向滚动不会互相误触。
- 周、月、学期任务不会出现在日计划，也不会彼此串联。
- 覆盖 375、390、768、834、1024、1366 和 1440px，无横向溢出或卡片变形。
- 键盘、焦点、对比度、200% 文本放大和减少动态效果通过验收。
- PWA 安装、离线打开、离线创建和完成任务继续通过。

## 14. 非目标

本次不实现：

- 从日任务自动生成周/月/学期任务。
- 跨层级同步完成状态。
- 任务依赖、子任务、重复任务或团队协作。
- 删除旧 `planTaskGroups`、`rangePlans` 表或清理其历史记录。
- 新的统计报表或 AI 自动拆解计划。

## 15. 完成定义

以下条件全部满足后可交付：

1. 每条任务只有一个 `scope + periodKey`，四个层级查询和进度完全隔离。
2. 现有任务安全迁移为日任务，跨日步骤成为独立日任务。
3. 周历、月历、跨日色带和周/月总体计划界面全部退出。
4. 日、周、月、学期页面使用统一清单视觉，并拥有正确周期导航与创建表单。
5. 四个层级均支持右滑完成、撤销、编辑和删除。
6. 手机和平板横竖屏布局简洁、可读、无变形和横向溢出。
7. 类型检查、代码规范、单元测试、浏览器测试和 PWA 离线验收全部通过。
