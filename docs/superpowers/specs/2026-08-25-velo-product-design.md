# Velo 产品设计规格

- 日期：2026-08-25
- 状态：待用户验收
- 产品名称：Velo
- 中文释义：微流，仅用于品牌故事，不显示在应用主导航或 Logo 中
- 宣传口号：捕捉灵感，保持心流 / Catch ideas, keep flowing

## 1. 产品目标

Velo 服务大学生的日常学习全过程：先在主页了解学习状态，再进入独立的学习计划、知识笔记和专注工作台。产品以快速记录、低干扰组织和可控的 AI 辅助为核心，帮助学生把任务、课堂资料和个人理解转化为可持续复习的知识。

成功标准：

1. 用户无需注册即可在手机、平板和桌面浏览器安装并使用 PWA。
2. 用户能在 30 秒内新建任务或笔记，在 3 次操作内开始番茄钟。
3. 所有核心数据默认保存在当前设备，离线时仍可查看和编辑计划、笔记与便签。
4. AI 永远不在未经确认时改写正文或直接归档识别结果。
5. 375px 至 1440px 宽度内无横向滚动、关键功能缺失或不可读文字。

## 2. 产品结构

Velo 设五个入口，主页不是计划页：

1. **主页驾驶舱**：显示今日任务进度、下一项任务、最近笔记，以及新建笔记、拍照录入、开始专注三个快捷入口。
2. **学习计划**：日、周、月、学期四套彼此独立的计划视图。
3. **知识笔记**：自由嵌套的树状目录、富文本编辑器、AI 解释、拍照整理和知识批注。
4. **专注**：独立番茄钟页面，也可从主页和任务卡片启动；计时状态跨页面保持。
5. **设置**：本地数据、备份、PWA、AI 服务和无障碍偏好。

手机底部导航固定为首页、计划、笔记、专注；设置从顶部个人/更多菜单进入。平板和桌面使用左侧导航栏，设置固定在底部。

## 3. 学习计划

### 3.1 时间视图

- 日、周、月、学期计划独立创建、独立维护，不自动拆解或同步。
- 每个视图都以卡片呈现原子任务；一张卡片等于一个完成项，不包含子任务。
- 每个时间视图单独显示 `已完成任务数 / 总任务数` 进度条，所有任务权重相同。
- 周期结束后保留原始记录；未完成任务留在原周期，并提示用户复制到下一周期。

### 3.2 任务卡片

必填字段为标题与所属时间周期。可选字段包括学科、预计时长、备注、排序和关联笔记。任务可选关联知识树中的文件夹或笔记，但两套工作台的数据、完成状态和生命周期保持独立。

任务支持创建、编辑、勾选完成、恢复未完成、删除确认、触摸长按排序和一键开始专注。空视图显示明确的新建入口；完成所有任务后提供克制的成功反馈，不使用循环庆祝动画。

## 4. 知识笔记

### 4.1 树状目录

- 文件夹和笔记均可自由嵌套、重命名、排序与移动。
- 首次使用提供“学期 → 学科 → 章节”的快速创建模板，但不强制固定层级。
- 手机端目录使用抽屉；平板和桌面端目录常驻在编辑器左侧。
- 删除非空文件夹必须确认，并明确显示会影响的子项数量。

### 4.2 编辑器

正文使用富文本编辑体验，同时支持标题、列表、引用、任务列表、代码块、公式和常用 Markdown 快捷输入。编辑内容自动保存到本地数据库，并提供显式保存状态。

编辑器默认存储结构化文档 JSON，同时维护可搜索纯文本；导出时可转换为 Markdown。用户选中文本后显示统一工具条，至少包含 AI 解释和添加批注。

### 4.3 知识批注便签

- 批注锚定到选中文字，不直接修改正文。
- 便签分为疑问、重点、联想三类，并用标签与颜色共同表达类型。
- 手机点击高亮后从底部浮层打开；平板和桌面在右侧批注栏展示。
- 原文编辑导致锚点无法解析时，便签进入“待重新定位”，保留原引用文本与便签内容，不静默丢失。

## 5. AI 能力

### 5.1 用户自带 API

首版采用浏览器直连，不建立 Velo 中转服务。设置项包括 API 地址、API Key、文字模型和视觉模型；文字与视觉模型共享同一服务和 Key。保存前执行连接与跨域兼容性测试。

API Key 按用户要求长期保存在当前设备，并明确提示：共享设备不建议保存、清除浏览器数据会丢失、本地浏览器存储不等同系统密钥保险箱。Key、笔记和图片不发送到 Velo 自有服务器。

离线、跨域失败、限流、鉴权失败、模型不支持图片和响应格式异常都必须给出可恢复错误；用户原始内容与编辑进度不得因 AI 失败丢失。

### 5.2 划词解释

AI 结果默认显示在临时浮层：手机为底部浮层，平板和桌面为上下文侧边浮层。用户可以继续追问或点击“插入笔记”；未点击插入时正文保持不变。

### 5.3 拍照整理

首版支持相机拍摄和相册多图，不支持 PDF。流程为：

1. 连续拍摄或选择多张图片。
2. 本地检查方向、清晰度和文件大小，压缩为适合视觉模型的附件。
3. 将图片发送到用户配置的视觉模型。
4. 生成标题、内容摘要、核心知识点、概念解释、公式/图表说明和复习问题。
5. 对不确定内容标记“需核对”，不得猜测补全。
6. 用户预览、编辑并选择目标目录后才保存为新笔记。

压缩后的图片作为笔记附件保留，可单独查看或删除；删除附件不删除已经确认的笔记内容。

## 6. 专注与课堂能力

番茄钟提供 25 分钟专注、5 分钟短休息的默认值，并允许在设置中调整。计时使用目标结束时间计算，不依赖页面持续运行；后台或页面恢复后根据真实时间校准。计时结束提供可关闭的声音和系统通知，并尊重浏览器权限。

课堂语音识别放在后续独立里程碑。第一个版本只做稳定录音、课后转写、时间分段与知识总结，不做实时字幕。总结确认后提示用户导出或删除原始录音，避免长期占用浏览器空间。

## 7. 数据与离线架构

技术底座为 React、TypeScript、Vite 和 PWA。结构化本地数据存入 IndexedDB，附件以 Blob 保存；应用外壳和静态资源由 Service Worker 缓存。

核心实体至少包括：

- `PlanTask`：时间视图、周期键、标题、完成状态、排序和可选笔记关联。
- `KnowledgeNode`：父节点、类型、标题和排序。
- `NoteDocument`：结构化正文、搜索文本和保存时间。
- `Annotation`：文档、文本锚点、引用快照、类型、内容和重定位状态。
- `Attachment`：所属笔记、MIME 类型、Blob、压缩信息和创建时间。
- `FocusSession`：开始/结束时间、阶段、可选任务关联和完成状态。
- `AISettings`：服务地址、Key、文字模型、视觉模型和连接测试结果。

用户可以导出完整 JSON 备份，也可以把知识笔记导出为 Markdown 与附件压缩包；导入前进行版本校验并预览覆盖范围。设置页显示本地存储占用和清理入口。

## 8. 响应式与视觉系统

设计基准：

- [Web 主页方向](../../design/velo-web-home-direction.png)
- [手机版主页（已确认，包含最终选择的 Logo）](../../design/velo-mobile-home-approved.png)
- [Logo 方案 3 概念](../../design/velo-logo-concept-3.png)

视觉方向继承用户参考图的轻盈淡紫背景、黑色圆润标题、白色内容表面、蓝紫主色，以及珊瑚与薄荷色任务对象。彩色卡片只用于任务、状态或快捷动作；日常内容不堆叠成卡片墙。毛玻璃仅用于导航、底部栏、抽屉和临时浮层。

产品名称统一写作 `Velo`，不显示 `Velo {微流}`；界面左上角使用方案 3 的风格化小写字标 `velo`，其 `o` 带蓝紫开放流动切口。正式实现前须将概念图精修为可缩放 SVG，并验证单色、反白和小尺寸版本。功能图标统一采用同一套圆角线性矢量图标，禁止 emoji、字符图标和不一致的线宽。

基准宽度为 375/390px 手机、768/834px 平板、1024/1440px 桌面。触摸主操作目标不小于 44×44 CSS px；正文正常文字满足 WCAG 2.2 AA 4.5:1 对比度。

## 9. 动效系统

动效目标是解释状态变化和维持心流，而不是装饰：

- 页面切换使用共享轴移动与淡入，默认 220–320ms。
- 卡片按压轻微缩放，桌面悬停最多上移 2px；不使用导致布局跳动的缩放。
- 进度条在数据变化时平滑补间，首次加载不播放夸张入场。
- 任务完成后卡片收拢并重排，保持用户视线连续。
- 树节点展开使用高度与透明度过渡；抽屉和 AI/便签浮层采用柔和弹性进入。
- 便签出现使用短促的“揭起—落定”反馈，不循环晃动。
- 所有动效只使用 transform/opacity 等低成本属性，并为 `prefers-reduced-motion` 提供近乎即时的无位移动画。

动效验收要求：常规交互在 60Hz 设备上无明显卡顿，不阻塞点击，不延迟内容可读性；后台恢复、低性能和减少动态效果模式下仍保持功能完整。

## 10. 分阶段交付

产品分解为独立可验收里程碑，每个里程碑单独制定实施计划和分支：

1. **基础与主页**：React/TypeScript/Vite、PWA、IndexedDB、响应式应用壳、最终 Logo、主页驾驶舱和动效基础。
2. **学习计划**：四个独立时间视图、原子任务、数量进度和迁移提示。
3. **知识树与编辑器**：自由目录、模板、富文本、Markdown 快捷输入、搜索和导入导出。
4. **批注与专注**：文本锚点便签、重定位流程、番茄钟和通知。
5. **文字 AI**：BYOK 设置、连接测试、划词解释与可控插入。
6. **拍照整理**：相机/相册多图、压缩、视觉模型、预览确认和附件。
7. **课堂总结**：录音、课后转写、结构化知识总结和音频清理。

首个实施计划只覆盖里程碑 1，避免把整个产品一次性实现。

## 11. 验收与测试基线

- 单元测试覆盖计划进度、周期迁移、目录移动、锚点状态、计时恢复和数据迁移。
- 组件测试覆盖空、加载、错误、离线、禁用、完成、撤销和权限拒绝状态。
- 端到端测试覆盖主页快捷入口、任务完成、创建笔记、目录操作、添加批注、开始/恢复专注和完整备份恢复。
- 响应式检查覆盖 375、390、768、834、1024 和 1440px，并检查 200% 文本放大。
- 可访问性检查覆盖键盘顺序、可见焦点、读屏名称、对比度、触摸目标和减少动态效果。
- PWA 检查覆盖安装、离线启动、更新提示、缓存刷新和浏览器清除数据后的首次使用状态。
- AI 测试使用模拟服务覆盖成功、超时、限流、鉴权、跨域、无效 JSON 和不支持图片。

## 12. 首个里程碑的完成定义

里程碑 1 完成时，用户可以安装 Velo PWA，在手机、平板和桌面上看到与确认设计一致的主页驾驶舱；本地数据库已初始化；主页进度、下一任务、最近笔记与三个快捷入口使用真实本地示例数据；应用可离线重新打开；Logo、图标、响应式布局、基础动效和减少动态效果均通过自动化与浏览器检查。
