# Velow Notebook 里程碑 2：学习计划设计规格

- 日期：2026-08-28
- 状态：待用户审阅
- 产品：Velow Notebook
- 里程碑：2 — 学习计划
- 前置：里程碑 1 基础、首页与本地数据底座已完成
- 取代范围：本文件取代 `2026-08-25-velo-product-design.md` 中第 3 节及里程碑 2 的旧描述；其余产品方向继续有效

## 1. 目标

本里程碑交付一个手机、平板和桌面均可使用的本地优先学习计划工作台。学生只创建一次任务，日、周、月和学习周期视图从同一任务集合自动汇总；任务完成度按完成数量计算。学习周期同时覆盖学期、寒假、暑假和自定义假期。

成功标准：

1. 学生能在 30 秒内创建一项带日期的学习任务。
2. 同一任务在日、周、月和学习周期视图中的状态始终一致。
3. 学生可以通过右滑整条任务卡确认完成，不依赖复选框。
4. 学生可以长按拖动任务改期、改时或放回“待安排”。
5. 学期与假期可由学生自定义，未完成任务可由学生选择性复制到下一个学习周期。
6. 所有任务和学习周期数据默认保存在本机；刷新、离线重开和应用更新不得丢失。

## 2. 范围

### 2.1 本里程碑包含

- 自定义学期、寒假、暑假和其他假期的创建、编辑与删除保护。
- 日、周、月、学习周期四种汇总视图。
- 任务创建、编辑、删除、排序、改期、改时和完成/恢复。
- 当日、本周、本月和当前学习周期的数量进度。
- 逾期状态、空状态、保存失败与恢复提示。
- 跨学习周期未完成任务的选择性复制。
- 从任务进入专注页的入口与后续专注数据的接口约定。
- 响应式布局、触摸、键盘和减少动态效果支持。

### 2.2 本里程碑不包含

- 子任务、循环任务、优先级、提醒通知和多人协作。
- 任务与知识笔记的正式关联；此能力留到里程碑 3。
- 完整番茄钟及专注统计；此能力留到后续专注里程碑。
- 云同步、账户体系和跨设备共享。
- AI 自动排期、自动拆解任务或自动判断任务完成。

## 3. 核心模型

### 3.1 单一任务源

任务只创建一次，并归属一个具体日期。日、周、月和学习周期视图均为同一任务集合的不同查询与呈现，不创建多套独立任务，也不为假期任务建立第二张任务表。

- 日视图查询一个日期。
- 周视图查询自然周内的 7 个日期。
- 月视图查询自然月日期范围。
- 学习周期视图查询所选学期或假期的起止日期范围。
- 拖动或编辑任务日期后，所有视图和进度立即同步。

### 3.2 进度

所有任务权重相同：

```text
进度 = 已完成任务数量 / 当前视图任务总数
```

- 总数为 0 时显示 `0 / 0`，不显示误导性的 100%。
- 完成和恢复任务后，主页今日进度及所有相关计划视图实时更新。
- 预计时长和实际专注时长不参与完成度权重。

### 3.3 自定义学习周期

`LearningPeriod` 包含类型、名称、开始日期、结束日期和可选目标。类型包括学期、寒假、暑假和自定义假期，例如“2026 秋季学期”或“2027 寒假”。

- 同一日期最多属于一个学习周期；创建或修改造成时间范围重叠时，在日期字段附近提示并阻止保存。
- 任务根据 `scheduledDate` 动态归入对应学期或假期，不保存易失真的周期外键。
- 不在任何学习周期范围内的任务仍出现在日、周、月视图，并在周期上下文中标记为“未归属周期”。
- 修改周期范围只改变汇总归属，不修改任务日期或任务内容。
- 假期任务与普通任务使用相同字段、完成手势和进度算法。

## 4. 信息架构与视图

计划页顶部提供日、周、月、周期切换，并保留当前选中日期或学习周期上下文。

### 4.1 日视图

- 顶部显示日期、完成数量进度和预计剩余时长。
- “待安排”区域显示有日期但没有开始时间的任务。
- 时间轴区域显示设置了开始时间的任务。
- 任务按开始时间排序；同一时间按手动顺序和创建时间稳定排序。

### 4.2 周视图

- 显示连续 7 天及每天的完成数量。
- 手机以可横向切换的日期条配合选中日任务列表呈现，避免把 7 列压得不可读。
- 平板和桌面使用 7 日网格；任务可拖动到另一日期。

### 4.3 月视图

- 日期格只显示任务数量、完成数量和状态点，不在小格内堆叠完整标题。
- 点击日期后在手机底部面板或平板侧栏显示当日任务。
- 任务可拖动到其他日期；移动后所有汇总实时更新。

### 4.4 学习周期视图

- 显示所选学期或假期的类型、日期范围、目标、总进度、各月或各周的完成趋势和未完成数量。
- 未创建周期时显示一个明确的“创建第一个学期或假期”主操作。
- 周期选择器按时间顺序列出历史、当前和未来周期，并用类型标签区分学期、寒假、暑假和自定义假期。
- 历史周期默认只读浏览，但任务仍可从详情中编辑。

## 5. 任务编辑

### 5.1 字段

必填：

- `title`：任务名称。
- `scheduledDate`：计划日期。

可选：

- `subject`：学科。
- `startMinutes`：当天 0—1439 分钟内的开始时间。
- `estimatedMinutes`：预计时长，必须为正整数。
- `notes`：简短备注。

任务名称去除首尾空格后不得为空。字段错误紧邻对应输入显示；保存失败不得关闭编辑器或清空内容。

### 5.2 响应式编辑器

- 手机：从底部打开编辑面板，主按钮位于拇指可达区域并适配安全区。
- 横屏平板和桌面：从右侧打开抽屉，保留日历与时间轴上下文。
- 新建与编辑复用同一组件和字段规则。
- 标题与日期优先呈现；其他字段可跳过，不强迫学生填写完整表单。
- 所有触控目标至少 44×44 CSS px。

## 6. 任务条与交互

### 6.1 视觉规格

- 任务条填满时间轴或列表的可用内容宽度。
- 默认高度 54px，允许在 200% 文本放大时增高，但常规状态不因长标题增高。
- 标题单行截断；手机任务标题约 14px，卡片核心标题 16px，正文和按钮 13px，辅助信息不低于 12px。
- 色彩遵循约 60% 暖白/浅灰基底、30% 黑白灰信息层级、10% 强调色的节制比例；同一视图不把所有卡片和按钮都染成品牌紫。
- Velow 紫用于主操作、选中态、右滑完成和品牌识别；冷灰蓝用于时间轴与日程信息，低饱和青绿用于专注或积极状态，雾蓝与浅青只作为小面积标签和背景层。
- 推荐实现为语义色令牌而非组件内硬编码：品牌紫 `#901D78`、冷灰蓝 `#6176C7`、雾蓝 `#DCE5F6`、青绿 `#2D8F83`、浅青 `#DDF1EC`；所有颜色均需通过对比度验证。
- 未完成任务以中性浅灰为主，并通过学科标签或小型状态元素穿插冷色；禁止为了丰富而随机给每张卡片分配不同颜色。
- 完成任务使用低饱和紫灰毛玻璃表面、细边框和克制阴影，不使用单独的细进度条。

### 6.2 右滑完成

- 手指直接向右移动时进入完成手势；卡片内部显示具有品牌识别的 `Flow Arrow`。
- 高饱和 Velow 紫色从左向右填充整条卡片，填充量跟随手指位移。
- 横向移动达到卡片可用宽度约 70% 后，松手即确认完成；未达到阈值则回弹。
- 确认后填充补至 100%，文字变为“已完成”，随后过渡为低饱和紫灰毛玻璃完成态。
- 完成后显示 5 秒“撤销”提示；撤销恢复原状态与排序。
- 不显示复选框。键盘聚焦任务后可用 Enter/Space 完成，并可从更多菜单执行同一动作。

### 6.3 拖动与点击

- 点击任务打开编辑器。
- 长按约 350ms 后进入拖动，避免与直接右滑完成冲突。
- 拖到时间轴设置或修改开始时间。
- 拖到“待安排”移除开始时间，但保留日期。
- 周/月视图可拖到其他日期；移动后显示可撤销的轻提示。
- 键盘和不适合拖动的用户可从更多菜单选择“移动到日期/时间”。

### 6.4 删除

- 不提供左滑删除。
- 删除位于更多菜单，执行前使用可访问的确认对话框，并明确显示任务名称。
- 删除任务不删除学科分类，也不删除已经产生的历史专注记录。

## 7. 专注联动

- 任务详情和更多菜单提供“开始专注”。
- 有预计时长时建议合适的专注轮次；没有时默认 25 分钟。
- 番茄钟结束只记录一次专注，不自动把任务标为完成。
- 返回计划页后显示该任务累计的实际专注时长，学生仍需右滑确认任务完成。
- 本里程碑只交付入口和任务 ID 传递契约；完整计时与 `FocusSession` 写入由后续里程碑实现。

## 8. 跨学习周期迁移

进入新的学期或假期且上一学习周期存在未完成任务时，在计划页显示非阻塞提示条；不得自动复制、移动或弹出强制模态框。该流程同时支持“学期 → 假期”“假期 → 学期”和“学期 → 学期”。

流程：

1. 提示“上一学习周期还有 N 个任务未完成”，并显示来源周期名称。
2. 学生点击“查看整理”打开手机底部面板或平板侧栏。
3. 默认不全选；学生选择需要延续的任务。
4. 确认后复制为新任务，进入当前学习周期的“待安排”：如果今天位于目标周期内则使用今天，否则使用目标周期开始日；学生可在复制前后改期。
5. 复制项保留标题、学科、预计时长和备注，不继承完成状态、开始时间或旧日期。
6. 原任务及旧周期记录保持不变。
7. 学生可以“暂不处理”，并能从周期菜单重新打开整理入口。

复制动作必须是单个本地事务；部分失败时整体回滚并提示重试。

## 9. 状态与反馈

### 9.1 空状态

- 当天无任务：显示“今天还没有计划”和唯一主操作“新建任务”。
- 学习周期为空：显示创建第一个学期或假期的说明与主操作。
- 搜索或筛选无结果：保留清除筛选入口，不误导用户创建重复任务。

### 9.2 逾期

- `scheduledDate` 早于本地今天且未完成的任务标记为“已逾期”。
- 逾期任务留在原日期，不自动移到今天。
- 学生可以完成、编辑日期或拖动改期。

### 9.3 保存与错误

- 创建、编辑、完成、恢复、移动和复制均先写入 IndexedDB，再显示持久成功状态。
- 保存失败时在动作发生位置提示并保留用户输入；提供重试。
- 不使用只出现一次且无法恢复上下文的错误 Toast 作为唯一错误反馈。
- 应用离线时全部计划功能继续工作。

## 10. 本地数据设计

### 10.1 `PlanTask`

建议将当前任务模型演进为：

```ts
interface PlanTask {
  id: string
  title: string
  scheduledDate: string // 本地 YYYY-MM-DD
  startMinutes?: number // 0..1439
  subject?: string
  estimatedMinutes?: number
  notes?: string
  isCompleted: 0 | 1
  completedAt?: number
  order: number
  createdAt: number
  updatedAt: number
}
```

索引至少支持：

- `scheduledDate`
- `[scheduledDate+isCompleted]`
- `[scheduledDate+startMinutes]`
- `isCompleted`
- `updatedAt`

`order` 只用于相同日期、相同“待安排/时间段”内的稳定手动排序。

### 10.2 `LearningPeriod`

```ts
type LearningPeriodKind =
  | "semester"
  | "winter-break"
  | "summer-break"
  | "custom-break"

interface LearningPeriod {
  id: string
  kind: LearningPeriodKind
  name: string
  startDate: string // 本地 YYYY-MM-DD
  endDate: string   // 包含当天
  goal?: string
  createdAt: number
  updatedAt: number
}
```

学习周期重叠校验在领域服务和 UI 两层执行；IndexedDB 不提供区间唯一约束，因此保存事务中必须再次检查。

### 10.3 数据库升级

- 数据库继续使用现有内部名称，品牌改名不得创建空的新数据库。
- Dexie 增加新版本和 `learningPeriods` 表。
- 现有 `scope === "day"` 且 `periodKey` 为有效本地日期的任务迁移为 `scheduledDate = periodKey`。
- 无法可靠推导具体日期的旧任务不得静默丢弃或猜测日期；保留为“旧版计划待整理”，由学生选择日期后完成迁移。
- 升级过程必须可重复测试，并验证现有主页今日进度查询继续工作。

## 11. 动效与无障碍

- 交互反馈不超过 200ms；只动画 `transform` 和 `opacity`，手势填充用合成层或等效高性能实现。
- 右滑、回弹、完成和拖动均尊重 `prefers-reduced-motion`；减少动态效果时立即切换状态并保留清晰反馈。
- 循环动画不用于计划页。
- 任务条、日期、按钮和菜单均有可见焦点与可读名称。
- 状态不能只靠颜色表达；“已完成”“已逾期”和错误均有文字或图标标签。
- 完成手势、拖动和更多菜单均提供键盘等价操作。
- 200% 文本放大时允许任务条增高，内容不得裁切或重叠。

## 12. 查询与状态流

页面从 Dexie live query 获取任务与学习周期；数据库是持久状态的唯一来源。

```text
创建/编辑/拖动/完成
        ↓
领域校验与本地事务
        ↓
IndexedDB 持久化
        ↓
live query 更新
        ↓
日 / 周 / 月 / 学习周期 / 首页同步重绘
```

手势中的临时位移与填充属于组件瞬时状态，不提前写入数据库。只有达到阈值并确认后才提交完成状态。

## 13. 验收与测试

### 13.1 单元测试

- 日、周、月、学习周期日期范围计算，覆盖月末、跨年和闰日。
- 学期与假期类型校验、周期重叠检测、边界日期包含和未归属判断。
- 数量进度的 0/0、部分完成、全部完成与恢复。
- 逾期判断使用本地日期，不受 UTC 偏移破坏。
- 迁移复制字段规则与事务回滚。
- Dexie 旧版本升级及无法推导日期的数据保护。

### 13.2 组件与交互测试

- 创建、编辑、字段校验、保存失败和重试。
- 右滑未达阈值回弹、达到阈值完成、5 秒撤销。
- 长按拖动与右滑完成不互相误触。
- 删除确认、取消和确认路径。
- 空、逾期、无学习周期、遗留任务提示和迁移选择。
- 键盘完成、菜单移动、焦点回归和读屏名称。

### 13.3 端到端测试

- 创建任务后在四个视图及首页出现。
- 改期后所有视图与进度同步。
- 完成并撤销后数据库、首页和计划页一致。
- 创建学期和假期、拒绝重叠周期、修改范围并重新汇总。
- 创建假期任务后在日、周、月和假期视图中同步出现。
- 在“学期 → 假期”和“假期 → 学期”之间选择性复制任务，原任务保持不变。
- 离线刷新后任务、完成状态和学习周期仍可用。

### 13.4 响应式验收

覆盖 375、390、768、834、1024 和 1440px：

- 手机编辑器为底部面板，固定操作避开安全区。
- 横屏平板编辑器为右侧抽屉，日历上下文保持可见。
- 任务条填满内容列，常规高度约 54px，标题不撑高。
- 无横向页面滚动、文字重叠、不可达操作或小于 44px 的触控目标。

## 14. 完成定义

当以下条件全部满足时，里程碑 2 可验收：

1. 自定义学期、假期及单一任务源数据模型完成安全升级。
2. 日、周、月、学习周期视图使用真实本地数据并同步进度。
3. 任务 CRUD、右滑完成、撤销、长按拖动和删除保护可用。
4. 跨学习周期选择复制、逾期、空状态和错误恢复可用。
5. 手机和平板编辑器符合已确认布局和字号规范。
6. 自动化测试、响应式浏览器检查、键盘与减少动态效果检查通过。
7. README 和验收记录更新，现有主页与 PWA 行为无回归。
