# Velow Notebook：跨日学习任务设计规格

- 日期：2026-08-31
- 状态：待用户最终审阅
- 产品：Velow Notebook
- 适用范围：里程碑 2 学习计划的兼容式扩展
- 前置设计：`2026-08-28-velow-milestone-2-learning-plan-design.md`

## 1. 背景与目标

当前计划任务只保存一个 `scheduledDate`，适合“今天完成一项任务”，但无法准确表达“在几天内分多次完成一项学习目标”。如果把同一任务简单复制到多天，学生会失去整体进度和截止日期；如果只增加起止日期，又无法表达每天应该完成的行动。

本扩展引入“跨日任务组 + 单日学习步骤”：任务组保存整体目标和周期，步骤继续使用可在某一天完成、改期和排序的任务。日、周、月视图仍查询同一批具体步骤，不创建独立的周计划或月计划文档。

成功标准：

1. 学生可以创建一个带开始日期、截止日期和学习次数的跨日任务。
2. 系统根据日期范围和已有任务负担生成稳定、均匀的本地排期，并允许学生调整。
3. 每次学习可以独立右滑完成；整体进度由完成步骤数量自动得出。
4. 周视图能看出任务连续周期和实际学习节点，月视图能跨周延续任务带。
5. 逾期步骤不会被系统擅自移动；系统提出重排建议，学生确认后才写入。
6. 原有单日任务、日/周/月查询、完成手势和离线能力继续工作。

## 2. 已确认的产品决策

- 继续保留一个统一的“新建任务”入口，不增加“创建周计划”或“创建月计划”按钮。
- 创建时选择“单日任务”或“跨日任务”。
- 跨日任务采用“日期范围 + 学习次数”，不强制日期范围内每天都学习。
- 系统根据每天已有任务负担自动均匀排期，学生可在保存前修改。
- 逾期后提供重排建议，由学生确认；不得自动顺延。
- 进度继续按完成数量计算，父任务组不重复计数。
- 周视图使用连续任务带和学习节点；月视图使用可跨周续接的紧凑任务带。
- 右滑完成保留，并增加首次可发现性提示、紫色轨迹和递进式方向箭头。

## 3. 方案选择

### 3.1 未采用：只增加起止日期

优点是改动小，但无法表达学习次数、当天行动和真实进度，学生仍然不知道今天应该做什么。

### 3.2 未采用：按日期复制多个同名任务

每一天都能操作，但复制项之间没有可靠的整体关系。编辑目标、修改截止日期和计算总体进度都会产生重复或不一致。

### 3.3 采用：任务组与学习步骤分层

任务组是整体目标，学习步骤是实际行动。步骤复用现有任务能力，因此右滑完成、拖动改期、排序、离线持久化和日视图无需建立第二套交互模型；任务组只负责周期、生成规则和汇总。

## 4. 范围

### 4.1 本扩展包含

- 单日/跨日任务创建模式切换。
- 跨日任务组创建、查看、编辑和删除。
- 基于日期范围、学习次数和现有负担的本地排期建议。
- 可编辑的排期预览和步骤名称。
- 跨日任务总体进度及步骤完成/恢复。
- 周视图连续任务带、步骤节点及完成数量。
- 月视图跨周任务带和选中日期的具体步骤。
- 逾期步骤的“待调整”状态、重排建议和确认流程。
- 周期内拖动步骤，以及拖到周期外时的延长确认。
- 首次右滑提示、键盘与菜单等价操作、减少动态效果支持。
- Dexie 安全升级、原有任务兼容、事务与错误恢复。

### 4.2 本扩展不包含

- AI 根据语义自动拆解步骤内容。
- 云端排期、账户同步、通知提醒和多人协作。
- 循环任务、依赖关系、优先级和甘特图编辑器。
- 同一跨日任务在同一天安排多次学习；第一版要求学习次数不大于日期范围包含的自然日数量。
- 自动修改用户已经确认的日期。

## 5. 核心概念与数据模型

### 5.1 `PlanTaskGroup`

新增跨日任务组表：

```ts
interface PlanTaskGroup {
  id: string
  title: string
  subject?: string
  notes?: string
  startDate: string       // 本地 YYYY-MM-DD，包含当天
  endDate: string         // 本地 YYYY-MM-DD，包含当天
  sessionCount: number    // 正整数，且不超过范围内自然日数量
  estimatedMinutes?: number // 单次预计时长
  createdAt: number
  updatedAt: number
}
```

完成状态不存储在任务组中，而是由关联步骤实时派生：

```text
任务组进度 = 已完成步骤数量 / 全部步骤数量
```

全部步骤完成即视为任务组完成。任务组不进入日、周、月的完成数量分母，避免重复计数。

### 5.2 `PlanTask` 兼容式扩展

现有字段保持不变，增加可选关联：

```ts
interface PlanTask {
  // 现有字段不变
  groupId?: string
  stepIndex?: number // 从 1 开始，在同一任务组内唯一
  stepTitleMode?: "inherit" | "custom"
}
```

- 没有 `groupId` 的任务仍是普通单日任务。
- 有 `groupId` 的任务是跨日任务的具体学习步骤，仍拥有自己的 `scheduledDate`、标题、完成状态、排序和可选开始时间。
- 步骤默认标题为任务组标题，`stepTitleMode` 为 `inherit`，界面辅助信息显示 `第 N / M 次`；学生单独修改步骤标题后切换为 `custom`。
- 任务组标题和已自定义的步骤标题互不覆盖。只有 `stepTitleMode === "inherit"` 的未完成步骤在修改任务组标题时同步更新。

### 5.3 索引与一致性

- `planTaskGroups` 至少索引 `startDate`、`endDate` 和 `updatedAt`。
- `planTasks` 增加 `groupId` 与 `[groupId+stepIndex]` 索引。
- 同一任务组的 `stepIndex` 在领域服务中校验唯一和连续。
- 创建任务组和步骤、重新排期、调整学习次数、删除任务组均使用 Dexie 事务。
- 任务组的 `sessionCount` 必须与关联步骤数量一致；步骤不得引用不存在的任务组。

## 6. 自动排期规则

### 6.1 输入与校验

输入为开始日期、截止日期、学习次数和可选的单次预计时长：

- 开始日期不得晚于截止日期。
- 学习次数必须为正整数。
- 第一版每天最多安排该任务组的一次学习，因此学习次数不得超过日期范围包含的自然日数量。
- 所有日期均按本地日历日计算，不通过 UTC 字符串截断推导。

### 6.2 确定性排期

排期完全在本地完成，不依赖 API：

1. 截止日默认锚定最后一次学习。
2. 其余步骤先按时间跨度计算均匀分布的目标日期。
3. 在不打乱步骤顺序、不重复日期且不越界的前提下，比较目标日期附近候选日的任务负担。
4. 负担以当天已有任务的预计时长为主；未填写预计时长的任务按 30 分钟估算，任务数量作为稳定的次级排序条件。
5. 负担相同时选择更接近均匀目标的位置，再按更早日期稳定排序。
6. 相同输入和相同现有任务集合必须得到相同结果。

排期结果只是建议。创建界面在保存前列出每次学习的日期和标题，学生可以直接修改。

### 6.3 后续 AI 接口

未来 AI 只负责提供步骤标题、预计时长或推荐日期。领域层仍验证日期范围、次数、顺序和冲突，用户仍需确认后写入。AI 不成为创建跨日任务的必需依赖。

## 7. 创建与编辑流程

### 7.1 统一入口

计划页继续使用一个“新建任务”主操作：

- 日视图预填当前日期。
- 周视图预填选中日期或当前周内的今天。
- 月视图预填用户选中的日历日期。
- 编辑器顶部使用“单日任务 / 跨日任务”分段控制。

### 7.2 跨日任务表单

字段顺序：

1. 任务名称与学科。
2. 开始日期和截止日期。
3. 学习次数。
4. 单次预计时长与总体备注。
5. 自动生成的排期预览。

手机使用底部面板，平板和桌面使用右侧抽屉。排期预览显示 `第 N 次`、日期、当日负担摘要和可编辑步骤标题。系统建议使用紫色小标识，日期负担使用冷蓝或青绿色提示，不把所有行都染成品牌紫。

### 7.3 编辑任务组

- 修改日期范围后，只为未完成步骤生成新的建议；已完成步骤保留历史日期。
- 增加学习次数时，在剩余范围内新增未来步骤。
- 减少学习次数时，优先选择最晚的未完成步骤作为删除候选，并要求确认。
- 若新的截止日期早于某个已完成步骤，阻止保存并解释冲突；不得改写历史完成日期。
- 任务组保存失败时保留全部输入和预览，不关闭编辑器。

### 7.4 删除

删除任务组前明确显示将删除的步骤数量。确认后删除任务组及其全部步骤；已有专注历史若已存在，只解除任务关联，不删除专注记录。

## 8. 视图设计

### 8.1 日视图

- 只显示当天实际安排的学习步骤，不显示没有安排在当天的父任务组。
- 步骤标题保持一行截断，辅助信息显示任务组名称、`第 N / M 次`和总体进度。
- 右滑只完成本次步骤；最后一个步骤完成后任务组自动进入完成态。

### 8.2 周视图

- 在日期列上方显示一条覆盖任务组起止范围的连续圆角任务带。
- 实际安排学习的日期显示步骤节点：已完成使用克制紫色，当前步骤使用冷蓝强调，未来步骤使用白色或低饱和紫灰。
- 任务带显示标题、日期范围和 `已完成 / 总次数`，不显示单独细进度条。
- 手机仍以日期条和选中日列表为主要操作区；连续任务带作为可横向查看的周期概览，避免压缩七列任务文字。
- 平板和桌面在七日网格中直接呈现完整任务带和步骤节点。

### 8.3 月视图

- 任务组在日历中以紧凑圆角任务带横跨日期。
- 跨周时分成多段，每一段保持同一语义颜色；段尾和下一段段首使用连续方向处理，表达同一任务仍在延续。
- 小格内不堆叠完整步骤卡。点击有步骤的日期后，在手机底部面板或平板侧栏展示具体步骤。
- 同一周任务带过多时优先显示未完成和临近截止任务，其余折叠为“还有 N 项”。

### 8.4 任务组详情

详情展示总目标、日期范围、总体 `N / M`、每次学习的状态和重新排期建议。学生可以编辑任务组、打开某个步骤、开始专注或删除任务组。

## 9. 完成手势与可发现性

- 右滑阈值继续遵循现有学习计划规格：达到任务条可用宽度约 70% 后松手确认，未达到则回弹。
- 手指移动时从左侧显露高饱和 Velow 紫轨迹和由弱到强的三段 `Flow Arrow`。
- 首次遇到可右滑任务时，任务条只执行一次克制的短距离右移并回弹，同时显示“右滑完成”。完成引导后在本地 `appMeta` 记录，不重复干扰。
- 确认完成后先填满轨迹，再过渡为低饱和紫灰毛玻璃完成态，并提供撤销。
- 跨日步骤完成后更新任务组汇总；不得把同组其他步骤一起完成。
- 键盘 Enter/Space 和操作菜单中的“标记完成”提供等价操作。
- `prefers-reduced-motion` 下取消提示位移动画，改用静态箭头和文字；状态反馈仍完整。

## 10. 改期与逾期

### 10.1 手动拖动

- 在任务组日期范围内拖动步骤时直接修改该步骤日期。
- 拖到范围外时先显示“同时延长任务周期至 YYYY-MM-DD？”；确认后事务内更新任务组边界和步骤日期，取消则恢复原位。
- 一次拖动只移动当前步骤，不自动调整其他已经确认的步骤。
- 若改期造成同组两次学习落在同一天，阻止保存并提示选择其他日期。

### 10.2 逾期待调整

`scheduledDate` 早于本地今天且未完成的跨日步骤派生为“待调整”：

- 视觉使用冷蓝灰而非警告红，并保留文字标签，状态不只靠颜色表达。
- 逾期步骤留在原日期，不能静默移动。
- 系统根据今天、剩余截止日期、剩余学习次数和每天负担生成新建议。
- 学生可“确认调整”或“保持原计划”。只有确认后才在事务中更新未完成步骤。
- 截止日前没有足够可用日期时，提供“延长截止日期”或“减少剩余次数”，不擅自选择。

## 11. 进度与查询

所有计划进度仍按可行动任务数量计算：

```text
视图进度 = 已完成的单日任务与学习步骤数量 / 视图内全部单日任务与学习步骤数量
```

- 父任务组不进入分子或分母。
- 日视图只统计当天步骤。
- 周/月/学习周期视图按步骤的 `scheduledDate` 统计，与普通任务一致。
- 任务组详情单独显示该组完成步骤数量。
- 任务组的连续任务带只提供上下文，不能在日历覆盖的每一天制造虚假的任务数量。
- 首页“下一项任务”可以选中当天未完成的跨日步骤，并显示其任务组进度。
- 周/月连续任务带按区间相交查询：`group.startDate <= viewEnd && group.endDate >= viewStart`；具体完成数量仍从关联步骤派生。

## 12. 数据流与事务

```text
填写跨日任务
    ↓
校验范围与学习次数
    ↓
本地排期建议 → 用户调整并确认
    ↓
单个 Dexie 事务创建任务组与全部步骤
    ↓
live query 更新日 / 周 / 月 / 首页
```

完成、撤销、改期和重排均先通过领域服务写入 IndexedDB，再由 live query 重绘。手势位移、排期预览和未确认建议属于临时界面状态，不提前写入数据库。

任务组与步骤的批量写入失败时整体回滚。界面恢复操作前状态、保留编辑内容并在动作位置提供重试；不能只显示转瞬即逝且无法恢复上下文的 Toast。

## 13. 数据库升级与兼容

- Dexie 新版本新增 `planTaskGroups` 表，并扩展 `planTasks` 索引。
- 现有任务不补写 `groupId`，自然保持单日任务语义。
- 数据库升级不改变现有任务的标题、日期、完成状态、排序或时间。
- 升级过程必须验证可从当前正式数据库版本直接打开，也必须验证重复打开不会重复生成数据。
- 若发现引用不存在任务组的步骤，应用应隔离为可恢复的普通单日任务并记录诊断信息，不得丢弃任务。

## 14. 无障碍、动效与视觉约束

- 维持黑白灰为主、Velow 紫点睛，并用冷蓝和低饱和青绿区分当前步骤、排期负担与待调整状态。
- 不用红色惩罚学生的逾期行为；严重保存错误仍可使用符合对比度的错误语义色。
- 所有触控目标至少 44×44 CSS px。
- 周/月任务带不能成为唯一入口；日期、步骤和更多菜单都可聚焦与操作。
- 任务组进度、完成、待调整和错误均提供文字，不只依赖颜色、位置或动效。
- 手势动画只使用 `transform`、`opacity` 或等效合成层属性，避免布局抖动。
- 200% 文本放大时允许任务条和详情行增高，标题和操作不得重叠。

## 15. 测试与验收

### 15.1 领域与数据测试

- 日期范围包含边界、跨月、跨年和闰日。
- 学习次数为 1、等于范围天数、超过范围天数及非法值。
- 排期均匀性、繁忙日期避让、截止日锚定、稳定排序和确定性结果。
- 创建任务组与步骤的事务成功和任意一步失败回滚。
- 增减次数只影响允许修改的未完成步骤。
- 拖出范围时的延长确认、取消和日期重复保护。
- 逾期重排建议、无可用日期和用户确认后的事务更新。
- 任务组进度派生及日/周/月分母不重复计数。
- 数据库升级保留所有现有单日任务。

### 15.2 组件与交互测试

- 单日/跨日切换、字段校验、排期预览编辑、保存失败和重试。
- 右滑提示只出现一次，滑动轨迹和箭头随位移显露。
- 未达阈值回弹、达到阈值只完成当前步骤、撤销恢复。
- 键盘和菜单能够完成相同行为。
- 逾期“待调整”、建议确认、保持原计划和冲突解释。
- 编辑任务组时已完成步骤保持不变。
- 删除确认明确显示任务组和关联步骤数量。

### 15.3 端到端与响应式验收

- 创建跨日任务后，步骤出现在正确的日、周、月和首页位置。
- 周视图任务带与节点正确，月视图跨周续接且点击日期能打开步骤。
- 完成一个步骤后所有视图和任务组详情同步为正确数量。
- 离线刷新后任务组、步骤、进度和提示状态继续存在。
- 覆盖 375、390、768、834、1024 和 1440px；无页面级横向滚动、日期遮挡或小于 44px 的操作。
- 验证鼠标、真实触摸指针、键盘、200% 文本放大和 `prefers-reduced-motion`。

## 16. 完成定义

以下条件全部满足后，跨日学习任务扩展可验收：

1. 单日任务无回归，现有数据库安全升级。
