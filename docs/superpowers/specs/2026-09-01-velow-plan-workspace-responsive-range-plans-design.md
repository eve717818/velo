# Velow Notebook 计划工作台响应式重构与周月总体计划设计规格

- 日期：2026-09-01
- 状态：待用户最终复核
- 产品：Velow Notebook
- 范围：计划工作台日、周、月、学期视图；任务完成手势；周/月总体计划
- 前置规格：`2026-08-28-velow-milestone-2-learning-plan-design.md`、`2026-08-31-velow-multiday-plan-task-design.md`

## 1. 背景与目标

当前计划工作台已经支持日、周、月、学习周期视图、单日与跨日任务、任务进度和右滑完成，但实际设备验收暴露出四类问题：

1. 右滑完成不够灵敏，任务卡缺少常驻的方向提示，用户难以发现手势。
2. 月历在手机与平板竖屏中可能超出背景容器，选中日期的任务列表在任务较多时会占满页面。
3. 平板横屏把月历、进度和学习周期挤在不协调的两列中，主内容和辅助卡片都偏小。
4. 学习周期页面操作按钮层级混乱，创建入口不明显，通用状态文案缺少日、周、月和学期语义。

同时，周视图和月视图目前只是任务查询结果，不能保存“整个周”或“整个月”的主题、目标与重点事项。

本次设计的目标是：

- 增加独立的周计划和月计划设定，同时继续以日期任务作为唯一任务数据源。
- 让月历在手机、平板竖屏和平板横屏中都保持完整、可读和可操作。
- 让任务完成手势无需教学也能被发现，并提升真实触摸操作的成功率。
- 将“周期”面向用户统一表达为“学期”，同时保留学期、寒假、暑假和自定义假期。
- 调整颜色、层级、动效和文案，使计划工作台延续 Velow 的安静专注感。

## 2. 核心原则

### 2.1 任务仍是单一数据源

周计划和月计划只保存范围级的意图，不复制或重新创建范围内任务。日、周、月、学期和首页继续查询同一批 `PlanTask` 与 `PlanTaskGroup`。

### 2.2 一个范围一份总体计划

每个自然周最多一份周计划，每个自然月最多一份月计划。再次保存同一范围时更新原记录，不生成副本。

### 2.3 主内容优先

日历、任务和范围计划入口是主内容。完成进度和当前学期是辅助信息，不得在平板横屏中通过挤压主内容来换取并排展示。

### 2.4 手势必须可发现且有等价操作

右滑完成保留为主要触摸操作，但箭头、文字状态、任务菜单和键盘操作共同表达其语义。任何状态都不能只依赖颜色或动画。

## 3. 周计划与月计划设定

### 3.1 用户入口

- 周视图标题区域提供“制定本周计划”。
- 月视图标题区域提供“制定本月计划”。
- 按钮包含加号图标和文字，触控区域不少于 44×44 CSS px。
- 已保存计划时，入口改为“查看 / 编辑计划”，旁边显示单行主题摘要。
- 入口位于视图标题区域，不放在内容列表底部，也不依赖浮动按钮。

### 3.2 抽屉形态

- 手机：从底部打开抽屉，主操作位于拇指可达区域并避开安全区。
- 平板竖屏、平板横屏和桌面：从右侧打开抽屉，背景中的周历或月历保持可见。
- 同一时间只允许一个计划抽屉或任务编辑抽屉处于打开状态。
- 打开时初始焦点进入抽屉标题或第一个字段；Esc 关闭；关闭后焦点返回触发按钮。
- 存在未保存修改时，关闭操作先确认是否放弃。

### 3.3 字段

每份总体计划包含：

- `theme`：计划主题，必填，去除首尾空格后不得为空。
- `goal`：总体目标，必填。
- `focusItems`：重点事项，0—5 条；空白项不保存。
- `note`：补充备注，可选。

抽屉只读显示当前范围的起止日期、任务总数和已完成数量，作为制定总体计划时的参考。任务不在抽屉中复制，也不通过总体计划改变日期。

### 3.4 保存行为

- 保存前执行字段级校验，错误紧邻对应字段显示。
- 保存成功后关闭抽屉并刷新标题区摘要。
- 保存失败时保持抽屉、焦点和全部输入，显示原位置错误与重试入口。
- 离线时正常保存到 IndexedDB；刷新和重新打开应用后内容仍存在。

## 4. 数据设计

新增范围计划模型：

```ts
export type RangePlanKind = "week" | "month"

export interface RangePlan {
  id: string
  kind: RangePlanKind
  rangeStart: string
  rangeEnd: string
  theme: string
  goal: string
  focusItems: string[]
  note?: string
  createdAt: number
  updatedAt: number
}
```

约束：

- 周计划 `rangeStart` 为自然周周一，`rangeEnd` 为同周周日。
- 月计划 `rangeStart` 为当月第一天，`rangeEnd` 为当月最后一天。
- `id` 使用确定性范围键，例如 `week:2026-08-31`、`month:2026-09`。
- 数据服务保存前重新计算并校验范围，不能信任界面传入的结束日期。
- IndexedDB 新增 `rangePlans` 表；已有任务、任务组、学期和应用元数据不迁移、不重写。
- 创建与更新通过单个事务完成；同一范围保存采用 upsert 语义。

建议索引：

```text
&id, kind, rangeStart, rangeEnd, updatedAt
```

## 5. 响应式信息架构

### 5.1 手机

- 周视图使用横向日期条和选中日期任务列表。
- 月视图的日历放入完整宽度的背景卡片，七列等宽，禁止页面级横向滚动。
- 月历日期格只显示日期、任务总数和完成数量，不堆叠完整任务标题。
- 选中日期任务使用可折叠面板。折叠态显示日期、任务数量和最多两项预览；展开态最大高度约为视口的 45%，列表内部滚动。
- 范围计划入口放在视图标题区域右侧，并允许在窄屏中换到标题下方，不与标题重叠。

### 5.2 平板竖屏

- 周历或月历使用完整内容宽度，不与任务详情侧栏并排挤压。
- 月历日期格适当增高，七列仍为等宽网格。
- 选中日期任务位于日历下方的折叠面板，展开后内部滚动。
- 完成进度和当前学期优先并排；空间或文本放大不足时自动上下排列。

### 5.3 平板横屏与桌面

- 周/月主体使用完整工作区宽度，不再与两个狭窄辅助卡片组成固定左右列。
- 月计划主体内部约 65% 为日历，约 35% 为选中日期任务面板。
- 选中日期任务面板拥有独立滚动区域，不随任务数量无限拉长页面。
- 完成进度和当前学期移至主体下方，组成两个等宽信息卡。
- 周视图的七日网格占满主内容宽度，任务条允许在 200% 文本放大时增高。

### 5.4 月历防溢出规则

- 月历容器和每一级网格子项都允许收缩，使用 `min-width: 0`。
- 星期标题、周行和日期行统一使用七列 `minmax(0, 1fr)`。
- 不使用负边距把日历拉出卡片，不为日期格设置破坏窄屏的固定最小宽度。
- 日期数字、数量和选中态均在单元格内部，边框不增加网格总宽度。
- 所有目标宽度下，背景卡片、日历和任务面板均不得产生页面级横向滚动。

## 6. 选中日期任务面板

- 折叠态展示日期、星期、任务数量和最多两项任务摘要。
- 有更多任务时显示“另有 N 项”，而不是继续增长卡片高度。
- 点击面板标题或展开按钮切换状态，并使用 `aria-expanded` 与 `aria-controls`。
- 展开态完整使用现有 `TaskBar`，保留打开、右滑、长按拖动和键盘操作。
- 手机和平板竖屏使用下方折叠面板；平板横屏与桌面使用日历右侧固定面板。
- 改变选中日期时，面板滚动位置回到顶部；不自动展开或关闭。

## 7. 右滑完成交互

### 7.1 常驻提示

- 未完成任务左侧始终显示一个低对比度 Velow 流动箭头。
- 首次出现可滑任务时显示一次性文字提示“向右滑动完成”；提示状态保存在应用元数据中。
- 箭头不是完成勾选框，不可单独点击；任务卡仍是完整触控面。

### 7.2 方向与灵敏度

- 横向移动约 6px 后开始显示位移和填充反馈。
- 普通慢拖达到卡片可用宽度约 45% 后松手完成。
- 快速右甩在位移达到约 20% 且横向速度达到实现规定阈值时完成。
- 手势通过横向与纵向位移趋势判定：横向意图明确时进入完成，纵向意图明确时让页面继续滚动。
- 一旦进入横滑，取消长按拖动计时；一旦进入纵向滚动，取消完成与拖动候选。

### 7.3 视觉反馈

- Velow 紫色填充、任务卡位移和箭头亮度跟随手指进度。
- 未达到阈值时松手，卡片和填充平滑回弹。
- 达到阈值时箭头短暂向前推进，填充补满，状态文字改为“已完成”。
- 最终完成态为低饱和紫灰毛玻璃表面、细边框和克制阴影。
- 不使用勾选框，不增加底部细进度条。
- 完成后提供 5 秒撤销；失败时恢复原状态并在任务位置提供重试。

### 7.4 等价操作与动效

- 键盘聚焦任务后，Enter 或 Space 切换完成状态。
- 任务菜单提供完成或恢复操作。
- 所有非必要动效尊重 `prefers-reduced-motion`；减少动态效果时直接切换状态并保留文字反馈。
- 动效优先使用 `transform` 和 `opacity`，避免通过宽度和位置触发布局抖动。

## 8. 学期与假期页面

### 8.1 命名

- 顶部视图切换标签从“周期”改为“学期”。
- 页面标题和说明使用“学期与假期”，明确寒假、暑假和自定义假期仍受支持。
- 日、周、月辅助卡片的“学习周期”改为“当前学期”。
- 当前日期不属于任何范围时显示“当前日期未归属学期或假期”。

内部类型名和路由值可继续保留 `period`，避免无价值的数据迁移；用户可见文案必须统一。

### 8.2 创建与操作层级

- “＋ 新建学期 / 假期”位于学期页面顶部，使用明确的紫色主按钮。
- 当前学期概览只展示类型、名称、日期、目标和进度。
- 概览右上角提供一个有可读名称的“更多”按钮。
- “编辑学期”“处理上学期任务”“删除学期”进入更多菜单。
- 删除操作使用危险语义色文字并保留二次确认；菜单不能只靠颜色区分危险动作。
- 历史学期继续保持只读概览逻辑；允许从任务详情编辑任务。

## 9. 进度文案

`PlanProgress` 接收当前视图语义，不再使用“这个范围已经完成”。

- `total === 0`：`当前还没有任务`
- `0 < completed < total`：`已完成 X 项，还有 Y 项`
- 日视图全部完成：`今日任务已全部完成`
- 周视图全部完成：`本周任务已全部完成`
- 月视图全部完成：`本月任务已全部完成`
- 学期视图全部完成：`本学期任务已全部完成`

进度数字继续按完成任务数量计算，预计时长不参与权重。

## 10. 视觉系统

- 约 60% 暖白和浅灰基底、30% 黑白灰信息层级、10% 强调色。
- 新版 Velow 紫用于范围计划主操作、选中状态、右滑填充和品牌识别。
- 冷灰蓝用于日历结构、日期信息和非主状态。
- 低饱和青绿用于积极状态、完成进度或专注关联，不与品牌紫竞争。
- 完成任务采用紫灰雾面玻璃，不使用高饱和整卡常驻填充。
- 卡片文字、图标和状态必须通过对比度检查；状态不只依赖颜色。
- 保持现有圆角与柔和阴影语言，但减少同一层级中多个相似大卡片互相竞争。

## 11. 组件边界

建议新增：

- `RangePlanDrawer`：范围计划表单、抽屉焦点管理、保存与错误状态。
- `RangePlanSummary`：标题区入口、主题摘要和创建/编辑文案。
- `SelectedDayTaskPanel`：月视图的折叠/侧栏任务容器。
- `RangePlan` 领域校验、日期范围计算和数据服务。

建议调整：

- `PlansPage`：管理范围计划抽屉入口与当前视图语义。
- `MonthPlanView`：只负责日历、日期选择、跨日任务带和选中日面板编排。
- `WeekPlanView`：增加范围计划摘要插槽，保持现有任务查询。
- `TaskBar`：手势方向锁定、速度判定、常驻箭头和首次提示。
- `LearningPeriodView`：顶部创建入口与更多菜单。
- `PlanProgress`：接收视图并生成具体文案。
- `PlansPage.module.css` 与 `TaskBar.module.css`：响应式网格、折叠面板和手势动效。

## 12. 数据流与错误恢复

```text
打开周/月计划抽屉
        ↓
按范围键读取 RangePlan
        ↓
编辑本地草稿并校验
        ↓
IndexedDB 事务 upsert
        ↓
live query 更新标题摘要
```

```text
任务右滑达到阈值
        ↓
提交完成状态事务
        ↓
成功：所有视图同步 + 5 秒撤销
失败：恢复任务原状态 + 原位置重试
```

不得用不可恢复的 Toast 作为唯一错误反馈，不得在保存失败后清空用户输入。

## 13. 测试与验收

### 13.1 领域与数据测试

- 周范围覆盖跨月、跨年；月范围覆盖闰年二月。
- 周/月范围键稳定且互不冲突。
- 同一范围首次保存创建、再次保存更新，记录数保持为一。
- 主题与目标空白、重点事项超过五条、结束日期被篡改时拒绝保存。
- 数据库升级保留所有已有任务、任务组、学期和应用元数据。
- 事务失败不产生半条范围计划。

### 13.2 组件测试

- 周/月入口在无计划时显示“制定”，有计划时显示“查看 / 编辑”和摘要。
- 手机底部抽屉与平板右侧抽屉使用相同表单行为。
- 未保存关闭确认、保存失败、重试、焦点进入和焦点返回。
- 月任务面板折叠、展开、超过两项摘要和内部滚动。
- 学期顶部创建按钮、更多菜单、危险操作和文案。
- 进度的 0/0、部分完成以及日、周、月、学期全部完成文案。

### 13.3 手势测试

- 小于 6px 不进入滑动反馈。
- 慢拖未达到 45% 回弹，达到阈值只完成一次。
- 快速右甩达到位移和速度阈值时完成。
- 竖向滚动不完成任务，横滑后不触发长按拖动。
- 长按拖动仍可改期，点击仍可打开任务操作。
- 常驻箭头、一次性提示、完成态、撤销和保存失败恢复。
- 键盘 Enter/Space 与任务菜单产生等价结果。

### 13.4 响应式浏览器验收

覆盖 375、390、768、834、1024、1366 和 1440px：

- 月历完全位于背景卡片内，无页面级横向滚动。
- 平板竖屏日历使用完整宽度，日期格和数量不重叠。
- 平板横屏周/月主体为全宽，进度和当前学期位于下方等宽卡片。
- 选中日期大量任务不会无限拉长页面。
- 范围计划入口、学期创建入口和更多按钮均清晰可见且不少于 44px。
- 200% 文本放大时允许任务条和信息卡增高，文字不裁切。
- `prefers-reduced-motion` 下无多余位移动画，状态反馈仍完整。

## 14. 完成定义

以下条件全部满足后，本次重构可验收：

1. 每个自然周或自然月可创建、查看、编辑一份范围计划，离线持久化且不复制任务。
2. 手机、平板竖屏和平板横屏的周/月布局符合本规格，无日历溢出或小卡片挤压。
3. 选中日期任务面板可折叠或独立滚动，大量任务不占满页面。
4. 右滑箭头常驻、手势更灵敏、快甩可用，且不破坏竖向滚动和长按拖动。
5. 用户可见“周期”统一改为“学期”，学期操作层级和创建入口清晰。
6. 完成进度使用日、周、月、学期具体文案，不再显示“这个范围已经完成”。
7. 自动化测试、响应式浏览器检查、键盘、焦点和减少动态效果验收全部通过。
